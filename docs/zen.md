# Дзен Python

Увага! Цю статтю було створено за участі генеративних нейронних мереж.

---

Спільнота розробників Python дотримується специфічної філософії, відомої як «The Zen of Python» («Дзен Пайтона»). Текст цього афоризмного набору можна вивести в Python, виконавши (лише один раз за сесію):

    import this

Український переклад Дзен Python:

- Гарне переважає потворне.
- Очевидне краще за неочевидне.
- Просте переважає складне.
- Складне переважає заплутане.
- Плоске краще за вкладене.
- Розділене краще за щільне.
- Читабельність має значення.
- Особливі випадки не виправдовують порушення правил.
- Практичність важливіша за бездоганність.
- Помилки не повинні залишатися непоміченими.
- За певних умов можна замовчувати помилки.
- У разі невизначеності краще уникнути спроби вгадати.
- Повинен бути лише один — і, бажано, єдиний — зрозумілий спосіб зробити це.
- Можливо, цей спосіб спочатку не буде однозначним, якщо ви не голландець.
- Зараз краще, ніж ніколи.
- Часто ніколи кращим за просто "зараз".
- Якщо важко пояснити реалізацію, задум не найкращий.
- Якщо пояснення просте — можливо, задум дійсно гарний.
- Простори імен — чудова річ, давайте створювати їх більше!

Ці принципи допомагають зрозуміти сутність Python та його ефективне використання. Але як виникли ці принципи?

## Витоки філософії Python

Ідея створити єдиний документ, який би відображав ключові принципи Python, з’явилася у 1999 році. Саме тоді розробники, що переходили з інших мов, приносили свої усталені підходи, які не завжди відображали справжню природу Python. У той час Тім Пітерс, видатний інженер і співрозробник ядра Python, запропонував 19 принципів у формі жартівливих афоризмів. Цей підхід показував, що їх не слід сприймати як строгі правила, а як джерело натхнення для програмістів. Так з’явився Дзен Python.

Згодом афоризми Дзен набули великої популярності серед розробників, вплинувши на розвиток мови, і були враховані в офіційних пропозиціях для вдосконалення Python (PEP), зокрема в [PEP 20](https://peps.python.org/pep-0020/).

## Реалізація Дзена

Історія створення модуля `this`, що містить Дзен Python, також не позбавлена курйозів.

У 2001 році компанія Foretec організовувала десяту міжнародну конференцію Python (IPC 10). Тоді Foretec, як організатор заходів, шукала слоган для футболок, тому оголосила конкурс у спільноті Python.

Було отримано безліч варіантів, з яких більшість Тім Пітерс відкидав. Проте він обрав найцікавіші, а пізніше разом із Баррі Варсо, одним із розробників, провів голосування, що з кожним кроком скорочувало список до кінцевих двох варіантів.

1. "Bite off all you like — Chewing is optional" (перекладається як "Відкусите скільки завгодно — жувати необов’язково")
2. "import this" (імпортуйте це)

Після того, як був обраний варіант "import this", Баррі Варсо вирішив, що варто це втілити в життя. Незабаром з’явився Python 2.2, і він запропонував відключити повідомлення про завантаження модулів та включити новий модуль this, який при імпорті виводив би Дзен Python. Після завершення конференції IPC 10 Гвідо, Тім і Баррі у супроводі релізу Python 2.2.1 втілили цю ідею, нікому не сказавши про це. Більш того, вони не обмежилися звичайним розміщенням тексту – принципи були навмисно модифіковані за допомогою шифру [ROT-13](https://ru.wikipedia.org/wiki/ROT13), щоб трохи їх заплутати.

Модуль this став однією з безлічі пасхалок Python, на виявлення яких було витрачено достатньо багато часу.

Якщо подивитися на вихідний код цього модуля, можна побачити, що він сам порушує багато принципів Дзену. Код не виглядає гарним і читабельним, що ускладнює пояснення його реалізації. Крім того, однолітерні імена змінних є незрозумілими, а їхнє оголошення в глобальній області видимості просто ігнорує простори імен.

## Пасхалки Дзена

З Дзеном Python пов’язано ще кілька пасхалок.

### Пасхалка 1

Початково Тім Пітерс замислював 20 афоризмів, останній із яких залишив порожнім, запропонувавши написати його Гвідо ван Россуму. Творець Python віддав перевагу не додавати 20-й принцип, і до сьогодні він залишається порожнім.

### Пасхалка 2

Деякі з принципів Дзену самі по собі є пасхалками. Наприклад, один з принципів звучить так:

> There should be one-- and preferably only one --obvious way to do it. (Повинен існувати один, і, бажано, лише один очевидний спосіб зробити це.)

Зверніть увагу на те, як у оригіналі записані дефіси. Перший з них відокремлюється пробілом тільки з правого боку, а другий — тільки з лівого. Одного разу Тіму Пітерсу вказали на цю граматичну помилку, але він сказав, що це зроблено навмисно і ніколи не буде змінено.

Справа у тому, що існують два способи написання дефіса — з пробілами або без них. Тим вирішив обрати третій варіант — по одному пробілу з обох боків, позначивши це як жарт з принципу, в якому йдеться, що повинен існувати лише один очевидний спосіб щось зробити.

Слід зазначити, що цей принцип є насмішкою над програмістами Perl, головним девізом яких є "There is more than one way to do it" (Існує більше ніж один спосіб зробити це). У 1990-х та на початку 2000-х мовою Perl і Python були запеклими конкурентами, тому в їхніх спільнотах існувало дружнє суперництво.

### Пасхалка 3

Ще один принцип Дзен Python, який випливає з описаного вище та йде одразу за ним, також є пасхалкою:

> Although that way may not be obvious at first unless you're Dutch. (Хоч він може спочатку бути неочевидним, якщо ви не голландець.)

Це відсилання до творця мови Гвідо ван Россуму, оскільки він родом із Нідерландів. Гвідо відомий як "доброзичливий довічний диктатор" Python, який користується великою повагою та має величезний вплив на мову та її еволюцію. Хоча у 2018 році він покинув цю посаду, проте все одно залишається ключовою фігурою у спільноті Python.

---

Дзен Python підкреслює важливість простоти, ясності, зручності для читання та узгодженості коду. Ці принципи описують загальні правила проектування програм на мові Python та філософію дизайну цієї мови.

До речі, автори Python завжди відзначалися чудовим почуттям гумору та люблять пожартувати, тому приховали пасхалки не лише в Дзені, а й багато де ще. Наприклад, однією з них є команда 

    import antigravity
    
при запуску якої вас перенаправить на сайт зі скетчами на тему Python.
