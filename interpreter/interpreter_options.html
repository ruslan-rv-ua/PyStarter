Параметри командного рядка інтерпретатора

Загальне використання

python [option] ... [-c cmd | -m mod | file | -] [arg] ...

Опція -b

Видавати попередження (Warning) при спробі неявного перетворення типів bytes або bytearray на str, а також при порівнянні bytes/bytearray з str або bytes з int. Якщо вказати -bb, замість попереджень будуть викликатися помилки (Error).

Коли використовувати: Ця опція корисна для виявлення потенційних проблем у коді, пов'язаних з неправильною обробкою байтових рядків та текстових рядків, особливо при переході з Python 2 на Python 3 або при роботі з даними, що можуть бути як текстовими, так і бінарними.

Припустимо, є код:

# test_b_option.py
my_bytes = b"hello"
my_str = "world"
# print(my_bytes + my_str) # Це викличе TypeError напряму
print(my_bytes == "hello")

Запуск python -b test_b_option.py видасть BytesWarning.

Запуск python -bb test_b_option.py видасть BytesWarning як помилку, що перерве виконання.

Опція -B (та змінна середовища PYTHONDONTWRITEBYTECODE)

Забороняє Python створювати файли .pyc (скомпільований байт-код) під час імпорту модулів. Встановлення змінної середовища PYTHONDONTWRITEBYTECODE на будь-яке не порожнє значення має такий самий ефект.

Коли використовувати:

  • При розробці, коли зміни в коді відбуваються часто, і немає потреби в кешуванні байт-коду.
  • В обмежених середовищах, де запис файлів небажаний або неможливий (наприклад, деякі контейнери або системи лише для читання).
  • Для уникнення засмічення директорій файлами .pyc.

Приклад:

python -B my_script.py

Після виконання цього скрипта, якщо my_script.py імпортує інші модулі, для них не будуть створені .pyc файли.

Опція -c cmd

Дозволяє виконати команду Python, передану як рядок cmd. Ця опція завершує список опцій інтерпретатора, і всі наступні аргументи передаються команді як sys.argv.

Коли використовувати: Для виконання невеликих однорядкових скриптів без необхідності створювати окремий файл.

Приклад:

python -c "import os; print(os.getcwd())"

Ця команда виведе поточну робочу директорію.

python -c "import sys; print(sys.argv)" arg1 arg2

Виведе: ['<string>', 'arg1', 'arg2'] (або ['-c', 'arg1', 'arg2'] в деяких версіях Python для sys.argv[0]).

Опція -d (та змінна середовища PYTHONDEBUG)

Вмикає вивід налагоджувальної інформації парсера. Ця опція призначена переважно для розробників самого Python і працює лише на спеціальних налагоджувальних збірках інтерпретатора. Встановлення змінної середовища PYTHONDEBUG має схожий ефект.

Коли використовувати: Дуже рідко, переважно при розробці або налагодженні самого інтерпретатора Python або його розширень, що взаємодіють з парсером на низькому рівні.

Опція -E (та змінна середовища PYTHONIGNOREENVIRONMENT)

Змушує Python ігнорувати всі змінні середовища PYTHON*, такі як PYTHONPATH, PYTHONHOME, PYTHONSTARTUP, PYTHONDONTWRITEBYTECODE тощо.

Коли використовувати:

  • Для тестування скриптів у "чистому" середовищі, щоб переконатися, що вони не залежать від специфічних налаштувань середовища користувача.
  • При запуску скриптів у контрольованих середовищах, де змінні середовища можуть бути встановлені непередбачувано.

Приклад:

python -E my_script.py

Скрипт my_script.py буде виконано так, ніби змінні PYTHONPATH та інші не встановлені.

Опція -h, -?, --help

Виводить коротке довідкове повідомлення про опції командного рядка інтерпретатора Python та завершує роботу.

Коли використовувати: Коли потрібно швидко переглянути доступні опції та їх короткий опис.

Приклад:

python -h

Опція -i (та змінна середовища PYTHONINSPECT)

Після виконання скрипта (переданого як аргумент або через -c чи -m) переходить в інтерактивний режим. Це дозволяє перевірити стан глобальних змінних, викликати функції тощо. Також примусово вмикає інтерактивний режим, навіть якщо stdin не виглядає як термінал. Встановлення змінної середовища PYTHONINSPECT має такий самий ефект.

Коли використовувати:

  • Для налагодження скриптів: після їх виконання можна перевірити значення змінних, результати функцій.
  • Для швидкого тестування або експериментів з кодом модуля.

Приклад:

Припустимо, my_script.py містить:

# my_script.py
x = 10
y = 20
def my_func():
    return x + y

Запуск python -i my_script.py виконає скрипт, а потім відкриє інтерактивну сесію, де можна буде ввести x, y, my_func() для перевірки їх значень.

Опція -I (та змінна середовища PYTHONISOLATED)

Запускає Python в ізольованому режимі. Це означає, що одночасно вмикаються опції -E (ігнорувати змінні середовища PYTHON*) та -s (не додавати каталог site-packages користувача до sys.path). Також скриптова директорія та поточна директорія не додаються до sys.path, якщо це небезпечно (наприклад, якщо власник відрізняється).

Коли використовувати:

  • Для запуску скриптів у максимально ізольованому середовищі, щоб уникнути впливу конфігурації користувача або встановлених пакетів.
  • Для підвищення безпеки при виконанні потенційно ненадійного коду.

Приклад:

python -I my_script.py

Опція -m mod

Запускає модуль бібліотеки Python mod як скрипт. Модуль шукається в sys.path. Аргументи після mod передаються скрипту через sys.argv[1:].

Коли використовувати:

  • Для запуску вбудованих утиліт Python, таких як pip, venv, http.server.
  • Для запуску власних пакетів або модулів, які мають точку входу if __name__ == "__main__":.

Приклад:

python -m pip install requests (запускає модуль pip з командою install requests)

python -m http.server 8000 (запускає простий HTTP сервер на порті 8000)

python -m my_package.my_module arg1 (запускає my_module з пакету my_package)

Опція -O (та змінна середовища PYTHONOPTIMIZE)

Вмикає базову оптимізацію. При цьому видаляються оператори assert та будь-який код, що залежить від значення __debug__ (яке стає False). Скомпільовані файли байт-коду отримують розширення .opt-1.pyc. Встановлення змінної середовища PYTHONOPTIMIZE на не порожнє значення має такий самий ефект.

Коли використовувати:

  • Для невеликого підвищення продуктивності у виробничому середовищі, де перевірки assert вже не потрібні.
  • Слід бути обережним, оскільки це вимикає важливі перевірки, які можуть допомогти виявити помилки.

Приклад:

python -O my_script.py

Опція -OO

Вмикає більш агресивну оптимізацію. На додаток до дій опції -O, також видаляються рядки документації (docstrings) з байт-коду. Скомпільовані файли байт-коду отримують розширення .opt-2.pyc.

Коли використовувати:

  • Для максимального зменшення розміру скомпільованого коду та потенційного (але часто незначного) підвищення продуктивності.
  • Це може ускладнити налагодження, оскільки docstrings часто використовуються інструментами інтроспекції.

Приклад:

python -OO my_script.py

Опція -P (та змінна середовища PYTHONSAFEPATH)

Забороняє Python автоматично додавати до sys.path потенційно небезпечні шляхи. Це стосується випадків, коли скрипт запускається з директорії, власник якої відрізняється від поточного користувача, або коли поточна директорія може бути скомпрометована.

Коли використовувати: Для підвищення безпеки, особливо при запуску скриптів у середовищах, де є ризик атаки через маніпуляцію шляхами пошуку модулів.

Опція -q

Не друкувати повідомлення про версію інтерпретатора та авторські права при запуску Python в інтерактивному режимі.

Коли використовувати: Якщо потрібно "тихий" запуск інтерактивної сесії, наприклад, якщо вивід Python перенаправляється в іншу програму або лог-файл, і стандартне вітальне повідомлення є зайвим.

Приклад:

python -q (запускає інтерактивний режим без вітального повідомлення)

Опція -s (та змінна середовища PYTHONNOUSERSITE)

Забороняє додавання каталогу site-packages користувача до sys.path. Зазвичай цей каталог знаходиться в ~/.local/lib/pythonX.Y/site-packages (для Unix) або %APPDATA%\\Python\\PythonXY\\site-packages (для Windows) і використовується для встановлення пакетів без прав адміністратора (pip install --user).

Коли використовувати:

  • Для створення ізольованого середовища, де використовуються тільки системні пакети або пакети з віртуального середовища.
  • Для тестування, щоб переконатися, що скрипт не залежить від пакетів, встановлених користувачем.

Приклад:

python -s my_script.py

Опція -S

Забороняє автоматичний імпорт модуля site під час ініціалізації Python. Модуль site відповідає за додавання специфічних для сайту шляхів до sys.path (включаючи каталог site-packages користувача, якщо не вказано -s) та інші налаштування.

Коли використовувати:

  • У вбудованих системах або спеціалізованих середовищах, де стандартна поведінка site не потрібна або заважає.
  • Для максимального контролю над sys.path та процесом ініціалізації.
  • Увага: Використання -S може призвести до того, що багато стандартних пакетів не будуть знайдені, якщо їх шляхи не додані до sys.path вручну.

Опція -u (та змінна середовища PYTHONUNBUFFERED)

Примусово робить потоки стандартного виводу (stdout) та стандартного виводу помилок (stderr) небуферизованими. Це означає, що дані, записані в ці потоки (наприклад, через print()), будуть негайно виводитися, а не накопичуватися в буфері. Ця опція не впливає на стандартний ввід (stdin). Встановлення змінної середовища PYTHONUNBUFFERED на не порожнє значення має такий самий ефект.

Коли використовувати:

  • При перенаправленні виводу Python-скрипта в іншу програму або файл, і потрібно, щоб дані з'являлися негайно (наприклад, для логування в реальному часі).
  • При взаємодії з іншими процесами, які очікують негайної реакції.

Приклад:

python -u my_script.py | tee output.log

Вивід my_script.py буде одразу з'являтися на консолі та записуватися в output.log.

Опція -v (та змінна середовища PYTHONVERBOSE)

Вмикає детальний режим (verbose). При кожному імпорті модуля Python виводить повідомлення про те, звідки завантажується модуль. Якщо опцію вказати кілька разів (наприклад, -vv), рівень деталізації може збільшуватися (показуючи, наприклад, перевірку файлів, які не були знайдені). Встановлення змінної середовища PYTHONVERBOSE на ціле число, що відповідає кількості -v, має такий самий ефект.

Коли використовувати:

  • Для налагодження проблем з імпортом модулів (наприклад, щоб зрозуміти, чому імпортується не той модуль або модуль не знаходиться).
  • Для аналізу залежностей проекту.

Приклад:

python -v my_script.py

Виведе інформацію про кожен імпортований модуль та шлях до нього.

Опція -V, --version

Виводить номер версії інтерпретатора Python та завершує роботу. Якщо вказати двічі (-VV або --version --version), виводиться більше інформації про збірку Python.

Коли використовувати: Щоб швидко перевірити встановлену версію Python.

Приклад:

python -V (виведе, наприклад, Python 3.9.7)

python -VV (виведе більш детальну інформацію про версію та збірку)

Опція -W arg (та змінна середовища PYTHONWARNINGS)

Керує обробкою попереджень (warnings). Аргумент arg має формат action:message:category:module:lineno. Кожне поле, крім action, може бути порожнім (що означає відповідність будь-якому значенню).

  • action: може бути default, error, ignore, always, module, once.
  • message: текстовий рядок, що відповідає початку повідомлення попередження (регулярний вираз).
  • category: клас попередження (наприклад, DeprecationWarning, SyntaxWarning).
  • module: назва модуля, де виникло попередження (регулярний вираз).
  • lineno: номер рядка.

Можна вказувати кілька опцій -W. Змінна середовища PYTHONWARNINGS може містити список таких аргументів, розділених комою.

Коли використовувати:

  • Щоб приховати певні типи попереджень.
  • Щоб перетворити певні попередження на помилки (наприклад, DeprecationWarning під час розробки).
  • Для тонкого налаштування фільтрації попереджень.

Приклад:

python -W "ignore::DeprecationWarning" (ігнорувати всі DeprecationWarning)

python -W "error::UserWarning::my_module" (перетворити на помилки UserWarning з модуля my_module)

Опція -x

Пропускає перший рядок вихідного файлу скрипта. Це дозволяє використовувати нестандартні форми "shebang" (#!cmd), які не є сумісними з Unix, але можуть використовуватися, наприклад, у файлах .bat або .cmd у Windows для запуску Python скриптів.

Коли використовувати: Рідко, переважно для специфічних сценаріїв запуску на Windows, де перший рядок може містити команду, не призначену для інтерпретатора Python.

Опція -X opt

Встановлює специфічну для реалізації Python опцію. Назви доступних опцій можуть відрізнятися між різними реалізаціями Python (CPython, PyPy, Jython тощо) та версіями. Деякі поширені опції для CPython:

  • -X faulthandler: вмикає модуль faulthandler для виведення трасування стека при серйозних помилках (наприклад, segmentation fault).
  • -X importtime: показує час, витрачений на кожен імпорт (корисно з -v).
  • -X dev: вмикає "режим розробника", який додає додаткові перевірки та попередження, корисні під час розробки (наприклад, ResourceWarning).
  • -X utf8: вмикає UTF-8 режим для стандартних потоків та файлової системи, ігноруючи налаштування локалі.
  • -X pycache_prefix=DIR: встановлює префікс для каталогів з .pyc файлами замість __pycache__.

Коли використовувати: Для доступу до розширених або експериментальних функцій, або для тонкого налаштування поведінки інтерпретатора, специфічного для даної реалізації.

Приклад:

python -X dev my_script.py

python -X faulthandler my_script_that_crashes.py

python -X importtime -v my_app.py

Опція --check-hash-based-pycs always|default|never

Контролює, як Python перевіряє актуальність файлів .pyc (байт-коду), заснованих на хеші вихідного файлу.

  • default: Python перевіряє хеш або час модифікації вихідного файлу для визначення, чи потрібно перегенерувати .pyc.
  • always: Python завжди перевіряє хеш вихідного файлу. Це може бути повільніше, але надійніше, якщо час модифікації файлів може змінюватися без зміни вмісту.
  • never: Python ніколи не перевіряє хеш або час модифікації, припускаючи, що .pyc файли завжди актуальні. Це найшвидший варіант, але може призвести до використання застарілого байт-коду, якщо вихідні файли змінилися. Використовувати з обережністю.

Коли використовувати:

  • always: У випадках, коли система контролю версій або інші інструменти можуть змінювати час модифікації файлів без зміни їх вмісту.
  • never: У виробничих середовищах, де вихідні файли гарантовано не змінюються після розгортання, для максимальної швидкості завантаження модулів.

Приклад:

python --check-hash-based-pycs always my_script.py

Опція --help-env

Виводить довідку про змінні середовища, які впливають на поведінку Python, та завершує роботу.

Коли використовувати: Щоб дізнатися, які змінні середовища Python розпізнає та як вони використовуються.

Приклад:

python --help-env

Опція --help-xoptions

Виводить довідку про доступні специфічні для реалізації опції -X та завершує роботу.

Коли використовувати: Щоб дізнатися, які опції -X підтримуються поточною версією та реалізацією Python.

Приклад:

python --help-xoptions

Опція --help-all

Виводить повну довідкову інформацію про всі опції командного рядка, змінні середовища та інші аспекти запуску інтерпретатора Python, а потім завершує роботу.

Коли використовувати: Для отримання найповнішої довідки безпосередньо з командного рядка.

Приклад:

python --help-all

Аргумент file

Вказує шлях до файлу Python-скрипта (.py), який потрібно виконати. Python читає та виконує програму з цього файлу.

Коли використовувати: Це найпоширеніший спосіб запуску Python програм.

Приклад:

python my_application.py

python path/to/my_script.py

Аргумент - (дефіс)

Якщо як ім'я файлу вказано одинарний дефіс (-), Python читає програму зі стандартного потоку вводу (stdin). Якщо stdin підключено до терміналу, Python переходить в інтерактивний режим після виконання коду зі stdin (якщо не вказано -i, який примусово вмикає інтерактивний режим завжди).

Коли використовувати:

  • Для передачі коду Python в інтерпретатор через pipe з іншої програми.
  • Для швидкого виконання невеликих скриптів, введених безпосередньо в термінал (хоча для цього частіше використовується -c).

Ця команда передасть рядок print('Hello from stdin') на стандартний ввід Python, який його виконає.

Аргумент arg ...

Будь-які аргументи, що йдуть після імені файлу скрипта (або після команди для -c, або після імені модуля для -m), передаються безпосередньо скрипту.

Коли використовувати: Для передачі параметрів, шляхів до файлів, конфігураційних значень та іншої інформації в Python-скрипт під час його запуску.
