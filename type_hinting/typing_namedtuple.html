Іменовані кортежі

typing.NamedTuple — це фабрична функція для створення підкласів tuple з іменованими полями та підказками типів для цих полів. Вона поєднує переваги кортежів (незмінність, легкість) з читабельністю іменованих полів, подібно до об'єктів або словників.

Основні переваги використання NamedTuple:

  • Читабельність: Доступ до полів за іменем робить код зрозумілішим.
  • Підказки типів: Вбудована підтримка статичної типізації.
  • Незмінність (Immutability): Як і звичайні кортежі, екземпляри NamedTuple є незмінними.
  • Ефективність: Займають менше пам'яті, ніж звичайні об'єкти з __slots__ або словники для зберігання структурованих даних.
  • Сумісність з кортежами: NamedTuple є підкласом tuple, тому його можна використовувати скрізь, де очікується кортеж.

Створити NamedTuple дуже просто. Ви визначаєте клас, який успадковується від typing.NamedTuple, і вказуєте поля разом з їхніми типами.

from typing import NamedTuple

class Point(NamedTuple):
    x: float
    y: float

# Створення екземпляра
p1 = Point(1.0, 2.5)
p2 = Point(x=3.0, y=4.7)

Використовуємо:

>>> p1
Point(x=1.0, y=2.5)
>>> p2
Point(x=3.0, y=4.7)
>>> p2.x
3.0
>>> p2[1]
4.7
>>>

Поля NamedTuple є незмінними після створення екземпляра:

>>> p1.x = 5.0
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
AttributeError: can't set attribute
>>>

Як typing.NamedTuple, так і collections.namedtuple надають корисний метод _asdict(), який повертає звичайний dict, що містить усі поля та їхні значення:

>>> d = p1._asdict()
>>> type(d)
<class 'dict'>
>>> d
{'x': 1.0, 'y': 2.0}
>>> new_point = Point(**d)
>>> new_point
Point(x=1.0, y=2.0)
>>>

Метод _replace()

Оскільки екземпляри NamedTuple є немутабельними, ви не можете змінювати значення їхніх полів після створення. Однак, часто виникає потреба створити новий екземпляр, який є копією існуючого, але з одним або кількома зміненими полями. Для цього NamedTuple надає зручний метод _replace(). Метод приймає іменовані аргументи для полів, які ви хочете змінити.

>>> p = Point(1.0, 2.0)
>>> p2 = p._replace(y=-2.0)
>>> p2
Point(x=1.0, y=-2.0)
>>>

typing.NamedTuple vs collections.namedtuple

Хоча обидва створюють іменовані кортежі, typing.NamedTuple має кілька ключових відмінностей та переваг над collections.namedtuple:

  1. Підказки типів: typing.NamedTuple розроблений спеціально для використання з підказками типів. Це основна перевага.
  2. Синтаксис: typing.NamedTuple використовує синтаксис класів, що є більш сучасним та читабельним для багатьох розробників.
  3. Докстрінги та методи: Легше додавати докстрінги та методи до класів, створених за допомогою typing.NamedTuple.
  4. Значення за замовчуванням: typing.NamedTuple підтримує значення за замовчуванням для полів (починаючи з Python 3.7).

Значення за замовчуванням

Можна вказати значення за замовчуванням для полів. Поля зі значеннями за замовчуванням повинні йти після полів без них.

from typing import NamedTuple

class Config(NamedTuple):
    host: str
    port: int = 8080
    debug_mode: bool = False

Використання значень за замовчуванням

>>> conf1 = Config("localhost")
>>> conf1
Config(host='localhost', port=8080, debug_mode=False)
>>> conf2 = Config("example.com", port=9000, debug_mode=True)
>>> conf2
Config(host='example.com', port=9000, debug_mode=True)
>>>

Докстрінги та Методи

Оскільки NamedTuple створює звичайний клас, ви можете додавати до нього докстрінги та методи.

from typing import NamedTuple
import math

class Vector(NamedTuple):
    """Представляє 2D вектор з початком у (0,0)."""
    x: float
    y: float

    def magnitude(self) -> float:
        """Повертає довжину (модуль) вектора."""
        return math.sqrt(self.x**2 + self.y**2)

    def __str__(self) -> str:
        return f"Vector({self.x}, {self.y}) with magnitude {self.magnitude():.2f}"

v = Vector(3.0, 4.0)

Використання:

>>> v
Vector(x=3.0, y=4.0)
>>> print(v)
Vector(3.0, 4.0) with magnitude 5.00
>>> v.magnitude()
5.0
>>> help(v)
Help on Vector in module __main__ object:

class Vector(builtins.tuple)
 |  Vector(x: float, y: float)
 |
 |  Представляє 2D вектор з початком у (0,0).
 ...

Приклад: Клас Person 😊

Розглянемо практичний приклад з класом Person.

from typing import NamedTuple, Optional, List

class Address(NamedTuple):
    street: str
    city: str
    postal_code: str

class Person(NamedTuple):
    """Представляє особу з базовою інформацією."""
    first_name: str
    last_name: str
    age: int
    email: Optional[str] = None  # Поле може бути None
    address: Optional[Address] = None
    hobbies: List[str] = [] # Увага з мутабельними типами за замовчуванням!

    def full_name(self) -> str:
        """Повертає повне ім'я особи."""
        return f"{self.first_name} {self.last_name}"

    def can_vote(self) -> bool:
        """Перевіряє, чи може особа голосувати (вік 18+)."""
        return self.age >= 18

# Створення екземплярів
person1_addr = Address("вул. Хрещатик", "Київ", "01001")
person1 = Person(
    first_name="Іван",
    last_name="Петренко",
    age=30,
    email="ivan.petrenko@example.com",
    address=person1_addr,
    hobbies=["читання", "подорожі"]
)

person2 = Person(first_name="Марія", last_name="Коваленко", age=17)

Використання:

>>> person1
Person(first_name='Іван', last_name='Петренко', age=30, email='ivan.petrenko@example.com', address=Address(street='вул. Хрещатик', city='Київ', postal_code='01001'), hobbies=['читання', 'подорожі'])
>>> person2
Person(first_name='Марія', last_name='Коваленко', age=17, email=None, address=None, hobbies=[])
>>> person2.can_vote()
False
>>> person2.full_name
<bound method Person.full_name of Person(first_name='Марія', last_name='Коваленко', age=17, email=None, address=None, hobbies=[])>
>>> person2.full_name()
'Марія Коваленко'
>>>

Важливо

Як і у звичайних функціях Python, якщо ви використовуєте мутабельний тип (наприклад, list або dict) як значення за замовчуванням, цей об'єкт буде спільним для всіх екземплярів, які не надають власного значення для цього поля.

>>> p_test1 = Person(first_name="Тест1", last_name="Один", age=20)
>>> p_test2 = Person(first_name="Тест2", last_name="Два", age=22)
>>>
>>> p_test1.hobbies.append("плавання") # Це змінить список hobbies для p_test2 теж!
>>> p_test2.hobbies
['плавання']
>>>

Найкраще використовувати незмінні типи для полів NamedTuple, якщо це можливо, або бути обережним з мутабельними типами.

Успадкування

Обмеження успадкування

Ви можете успадковувати від NamedTuple, але є обмеження. NamedTuple не призначений для глибокої ієрархії успадкування. Якщо ви успадковуєте від NamedTuple, новий клас не зможе додавати нові поля.

from typing import NamedTuple

class Base(NamedTuple):
    id: int
    name: str

class Derived(Base):
    # Не можна додавати нові поля тут, наприклад:
    # description: str # Це призведе до TypeError

    def display(self) -> str:
        return f"ID: {this.id}, Name: {this.name}"

Якщо вам потрібна більш гнучка система успадкування з полями, краще розглянути звичайні класи або dataclasses.

Практики використання

Коли використовувати:

  • Прості структури даних: Коли вам потрібно зберігати невелику кількість атрибутів без складної логіки.
  • Повернення кількох значень з функції: Замість повернення звичайного кортежу, NamedTuple робить результат більш зрозумілим.
  • Конфігураційні об'єкти: Для зберігання налаштувань, які не змінюються під час виконання.
  • Елементи в колекціях: Коли ви працюєте зі списками або іншими колекціями однотипних структурованих даних.

Переваги:

  1. Читабельність коду: Іменовані поля значно покращують розуміння коду.
  2. Підтримка типів: Інтеграція з mypy та іншими статичними аналізаторами.
  3. Незмінність: Гарантує, що дані не будуть випадково змінені.
  4. Продуктивність: Зазвичай швидші та менш затратні по пам'яті, ніж звичайні об'єкти або словники для простих структур.
  5. Сумісність з кортежами: Можна розпаковувати, індексувати, ітерувати як звичайні кортежі.

Недоліки та Обмеження:

  1. Незмінність: Якщо вам потрібні об'єкти, стан яких можна змінювати, NamedTuple не підійде. Розгляньте dataclasses (з frozen=False) або звичайні класи.
  2. Обмежене успадкування: Не підходить для складних ієрархій класів, де дочірні класи додають нові поля.
  3. Значення за замовчуванням для мутабельних типів: Потребує обережності, як описано вище.

NamedTuple та dataclasses

Python 3.7+ ввів dataclasses, які пропонують схожу функціональність, але з більшою гнучкістю (наприклад, мутабельні екземпляри, легше успадкування з додаванням полів, default_factory).

  • Використовуйте NamedTuple, коли вам потрібна гарантована незмінність і сумісність з API, що очікують кортежі, а також максимальна простота для структур даних.
  • Використовуйте dataclasses, коли потрібна більша гнучкість: мутабельність, складніші значення за замовчуванням (через default_factory), успадкування з додаванням полів, або коли ви просто віддаєте перевагу їхньому синтаксису та можливостям. dataclass(frozen=True) може бути альтернативою NamedTuple.
