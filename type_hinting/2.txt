Я не понимаю смысла наследования протоколов.

Начну издалека. Python - объектно-ориентированный язык, поэтому там есть наследование. С помощью наследования реализуется номинальное подтипирование: при создании нового класса с помощью наследования мы явно описываем отношения между супер-классом и саб-классом. Насколько мне известно, номинальное подтипирование в Python зачастую используется при создании интерфейсов и их реализаций. Например, есть у нас интерфейс для загрузки изображений куда-то. Реализован такой интерфейс в виде ABC:

import abc

class ImageUploader(abc.ABC):
    @abc.abstractmethod
    def upload_image(self, image_bytes: bytes) -> int:
        raise NotImplementedError

Возможная реализация этого интерфейса может выглядеть так:

class ImageUploaderHTTP(ImageUploader):
    def upload_image(self, image_bytes: bytes) -> int:
        print(f"upload {len(image_bytes)} bytes to server")
        return 200

Одно из преимуществ номинального подтипирования - возможность использовать интерфейс в качестве аннотации типов там, где предполагается использовать реализации. По-другому удовлетворить статический анализатор типов, используя ABC, не выйдет. Как раз об этом я писал в начале этого года.

Таким образом, если мы хотим использовать статический анализатор типов и идти по пути чистого ООП, нам придется везде использовать абстрактные классы и наследование. Однако Python - это не статически типизированный язык программирования, и подобный подход к типизации не является единственным. Помимо номинального подтипирования, в Python существует структурное подтипирование. Реализовать структурное подтипирование можно с помощью объекта типа typing.Protocol. Так будет выглядеть предыдущий пример, реализованный с помощью структурного подтипирования:

from typing import Protocol

class ImageUploader(Protocol):
    def upload_image(self, image_bytes: bytes) -> int:
        ...

class ImageUploaderHTTP:
    def upload_image(image_bytes: bytes) -> int:
        print(f"upload {len(image_bytes)} bytes to server")
        return 200

Все то же самое, только без наследования. А статический анализатор типов теперь опирается не на MRO, а на структурное соответствие объекта типа ImageUploaderHTTP протоколу ImageUploader.

Итого, у нас есть abc для номинального подтипирования и typing.Protocol для структурного подтипирования. Подходы принципиально разные. Первый подход полагается на явные связи между классами, второй - на соответствие структуры класса структуре, описанной протоколом. Однако протоколы можно наследовать:

class ImageUploader(Protocol):
    def upload_image(self, image_bytes: bytes) -> int:
        ...

class ImageUploaderHTTP(ImageUploader):
    def upload_image(image_bytes: bytes) -> int:
        print(f"upload {len(image_bytes)} bytes to server")
        return 200

И этим пользуются. И это нарушает всю идею структурного подтипирования. Поэтому я не понимаю, зачем наследовать протоколы?
