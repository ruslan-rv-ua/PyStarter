Керування залежностями в Python: файл pyproject.toml

Управління залежностями в Python може бути складним завданням, що дратує, особливо для новачків. Легко захопитися установкою всіх потенційно корисних пакетів в одному віртуальному середовищі, що може призвести до конфліктів та "пекла залежностей".

Спочатку в Python для створення дистрибутивів використовувався пакет distutils. Потім з'явився setuptools, який був розширенням для distutils. Обидва інструменти використовували файл setup.py, в якому користувачі визначали залежності та метадані, що використовуються як частина дистрибутива для збірки пакету.

Файли setup.py, setup.cfg та requirements.txt пропонують різні способи роботи з залежностями в проектах Python. Проте, Python 3.6 представив новий стандартний файл конфігурації pyproject.toml, який спрощує управління залежностями та метаданими.

Формат TOML

TOML (Tom's Obvious Minimal Language) — це мінімальний формат файла конфігурації, який використовує розширення .toml.

Файли TOML складаються з:

  • Пар ключ/значення:
    • Ключі - це рядки, які не чутливі до регістру.
    • Значення можуть бути рядками, числами, булевими значеннями, датами/часом, масивами або таблицями.
  • Розділів/таблиць:
    • Використовуються для групування пов'язаних ключів.
    • Імена розділів чутливі до регістру.
  • Коментарів:
    • Починаються з # і продовжуються до кінця рядка.

Переваги TOML:

  • Простота: TOML легко читати та писати людям.
  • Чіткість: TOML має чітко визначену семантику, що полегшує аналіз.
  • Універсальність: TOML використовується в багатьох проектах Python, а також в інших мовах програмування.

Недоліки TOML:

  • Менш потужний, ніж інші формати: TOML не підтримує деякі складні структури даних, які можна знайти в інших форматах, таких як JSON.
  • Не має офіційного стандарту: Специфікація TOML все ще знаходиться в стадії розробки.

TOML часто використовується для конфігураційних файлів, опису метаданих проекту, зберігання даних.

pyproject.toml

Файл pyproject.toml був представлений як частина пропозиції щодо поліпшення PEP 518. Він визначає, як саме проекти Python повинні вказувати залежності збірки.

Усі залежності зберігаються у файлі, який знаходиться в кореневій директорії проекту і відповідає синтаксису TOML. Також містить метадані, такі як назва проекту, версія, опис, автор, ліцензія та іншу інформацію.

Одна з ключових характеристик файлу pyproject.toml — здатність визначати залежності проекту. Розробники можуть вказувати пакети та версії, необхідні для правильного запуску проекта. pyproject.toml забезпечує узгодженість проекту та гарантує можливість його відтворення іншими розробниками.

Файл pyproject.toml також підтримує концепцію extras, що дозволяє розробникам визначати додаткові залежності. Користувачі можуть встановлювати лише необхідні залежності для запуску проекта. Зазвичай, в розділі extras вказуються додаткові залежності, які використовуються у процесі тестування, наприклад pytest.

Крім стандартних метаданих та залежностей, файл pyproject.toml також підтримує данні налаштувань для сторонніх інструментів, таких як статичні аналізатори, засоби форматування та перевірки, такі як black і mypy.

pyproject.toml можна використовувати з інструментами керування залежностями пакетів, такими як pip, poetry, pdm, hatch та інші.

Переваги pyproject.toml

  • Універсальність: pyproject.toml використовується як з setuptools, так і з poetry.
  • Простота: чіткий та лаконічний синтаксис TOML.
  • Повторюваність: гарантує, що проект можна відтворити на інших машинах.
  • Розширюваність: підтримує настраиваемые поля для сторонніх інструментів.

Структура файлу pyproject.toml

1. Метадані проекта:

  • name: назва проекта
  • version: версія
  • description: опис
  • authors: автори
  • license: ліцензія
  • ...

2. Залежності:

  • build-system: інструменти для збирання (наприклад, poetry-core)
  • tool.<інструмент>.dependencies: пакети, необхідні для роботи інструмента (наприклад, pytest)
  • tool.<інструмент>.dev-dependencies: пакети, необхідні для розробки (наприклад, sphinx)
  • [tool.<інструмент>.extras]: додаткові пакети для певних сценаріїв (наприклад, docs)

Приклад файла pyproject.toml

На прикладі розглянемо файл для проекта, який використовує poetry:

[build-system]
requires = ["poetry-core>=1.0.0"]
build-backend = "poetry.core.masonry.api"

[tool.poetry]
name = "my-project"
version = "1.0.0"
description = "My Python project"
authors = ["John Doe <john@doe.com>"]
license = "MIT"

[tool.poetry.dependencies]
python = "^3.6"

[tool.poetry.dev-dependencies]
pytest = "^4.6"
mypy = "^0.942"
black = "^22.3.0"
isort = "^5.10.1"

[tool.mypy]
files = ["src/**/*.py"]
ignore_missing_imports = true
follow_imports = normal

[tool.black]
line-length = 88
target-version = py38

[tool.isort]
profile = "black"
line_length = 88
multi_line_output = 3
use_parentheses = True

Пояснення:

  • [build-system] та [tool.poetry]: стандартні секції для опису інструментів збирання та метаданих проекту.
  • [tool.poetry.dev-dependencies] : пакети, необхідні для розробки, включаючи mypy, black та isort.
  • [tool.mypy]: налаштування для mypy, включаючи ігнорування відсутніх імпортів та нормальне відстеження імпортів.
  • [tool.black]: налаштування для black, включаючи довжину рядка 88 символів та цільову версію Python 3.8.
  • [tool.isort]: налаштування для isort, включаючи профіль "black", довжину рядка 88 символів, та інші параметри форматування.

  • Poetry: Dependency Management and Packaging Made Easy
  • mypy: A Python type checker
  • Black: The uncompromising Python code formatter
  • isort: A Python utility/library to sort imports
