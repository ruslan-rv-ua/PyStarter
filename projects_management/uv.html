uv: універсальне рішення для проєктів Python

uv — це високошвидкісний менеджер пакунків та проєктів для Python. Написаний на Rust, він розроблений для оптимізації вашого робочого процесу, роблячи дії з керування проєктами значно швидшими. uv інтегрує різноманітні функціональності в єдиний інструмент, що робить його універсальним рішенням.

Основна ідея uv, як і інших інструментів на Rust в екосистемі Python (наприклад, Ruff), полягає у прискоренні вашого робочого процесу. Для встановлення пакунків uv може бути у 10-100 разів швидшим за pip. Крім того, uv об'єднує більшість функцій, що надаються такими інструментами, як pip, pip-tools, pipx, poetry, pyenv, twine, virtualenv та іншими.

Ключові можливості uv для керування вашими проєктами Python:

  • Швидке встановлення залежностей: Встановлює залежності дуже швидко, що особливо корисно для великих дерев залежностей.
  • Керування віртуальними середовищами: Автоматично створює та керує віртуальними середовищами.
  • Керування версіями Python: Дозволяє встановлювати та керувати кількома версіями Python, використовуючи дистрибутиви від Astral project.
  • Ініціалізація проєкту: Створює повну структуру проєкту Python, включаючи кореневу директорію, Git репозиторій, віртуальне середовище, pyproject.toml, README та інше.
  • Керування залежностями: Встановлює, оновлює, видаляє та фіксує прямі та транзитивні залежності, забезпечуючи відтворюваність середовища.
  • Керування збіркою та публікацією пакунків: Дозволяє створювати та публікувати пакунки у репозиторіях, таких як Python Package Index (PyPI).
  • Підтримка інструментів розробника: Встановлює та дозволяє запускати інструменти розробки, такі як pytest, Black та Ruff.

Окрім цих можливостей, uv є самостійним бінарним файлом, що спрощує встановлення та оновлення. Вам не потрібно мати встановлений Python у вашій системі, щоб встановити uv.

Встановлення uv

Для встановлення uv існує кілька варіантів. Найшвидший — використати самостійний інсталятор. Інший варіант — встановити uv з PyPI за допомогою pipx або pip. В офіційному посібнику з встановлення uv ви також знайдете опції використання Homebrew та Cargo.

Використання самостійного інсталятора:

Цей спосіб завантажує та встановлює останню бінарну версію uv у вашу систему. Команди залежать від операційної системи. Наприклад, для Linux + macOS:

$ curl -LsSf https://astral.sh/uv/install.sh | sh
Або, якщо у вас немає curl, можна використати wget: 
$ wget -qO- https://astral.sh/uv/install.sh | sh

Щоб встановити певну версію, можна додати номер версії до URL. Наприклад, для версії 0.6.12:

$ curl -LsSf https://astral.sh/uv/0.6.12/install.sh | sh

Після встановлення можна перевірити версію: 

$ uv --version

Встановлення з PyPI:

Ви можете встановити uv з PyPI за допомогою pipx. Це зробить uv доступним глобально у вашій системі.

$ pipx install uv

Для цього вам потрібен pipx. Можна також використати pip, але встановлення у системну інсталяцію Python не рекомендується.

Оновлення uv:

Якщо ви встановили uv за допомогою самостійного інсталятора, для оновлення до останньої версії використовуйте:

$ uv self update

Якщо ви встановили uv за допомогою pipx, для оновлення використовуйте:

$ pipx upgrade uv

Керування проєктами Python за допомогою uv

uv дозволяє швидко та ефективно створювати та керувати проєктами Python.

Створення проєкту:

Щоб створити та ініціалізувати проєкт, перейдіть до потрібної директорії та виконайте команду:

$ uv init <project_name>

Наприклад, uv init rpcats створить директорію rpcats/ зі структурою:

rpcats/
│
├── .git/
├── .gitignore
├── .python-version
├── README.md
├── main.py
└── pyproject.toml

Ця команда створює Git репозиторій, файл .gitignore з типовими виключеннями, файл .python-version для вказання версії Python, порожній README.md, файл main.py із заглушкою print("Hello..."), та файл pyproject.toml з базовою конфігурацією. Файл pyproject.toml містить дані проєкту під таблицею [project], які можна оновлювати.

Примітка: Щоб почати керувати існуючим проєктом, перейдіть до його директорії та виконайте uv init. Це створить необхідну структуру, але не перезапише існуючі main.py, Git репозиторій чи README.md. Однак, якщо у вас вже є pyproject.toml, команда не спрацює; його потрібно перемістити.

Запуск скрипта проєкту:

Після створення проєкту ви можете запустити головний скрипт (за замовчуванням main.py) за допомогою uv:

$ uv run main.py

При першому запуску, uv автоматично створить віртуальне середовище у папці .venv/ у корені проєкту та повідомить, яку версію Python використовує. uv також створить файл uv.lock.

Файл uv.lock:

uv.lock — це кросплатформний файл блокування, який містить точну інформацію про залежності вашого проєкту, що дозволяє іншим розробникам точно відтворити ваше робоче середовище. На відміну від pyproject.toml, який зазвичай містить прямі залежності, uv.lock містить точні версії всіх встановлених залежностей (прямих та транзитивних). Ви повинні додавати цей файл до системи контролю версій, але не повинні редагувати його вручну.

Керування залежностями за допомогою uv

uv спрощує керування залежностями, використовуючи чіткий робочий процес, який включає блокування залежностей для відтворюваності середовища.

Додавання та встановлення залежностей:

Для додавання залежностей використовуйте команду uv add:

$ uv add <package_name>

Ця команда додає пакунок до залежностей проєкту та встановлює його у віртуальне середовище проєкту. Наприклад, для додавання бібліотеки requests:

$ uv add requests

Команда uv add автоматично оновлює список залежностей у файлі pyproject.toml та відповідну інформацію у файлі uv.lock. uv add обробляє як прямі, так і транзитивні залежності.

Примітка: Якщо ви переходите з requirements.txt, можете імпортувати залежності за допомогою uv add -r requirements.txt. Важливо не використовувати інтерфейс pip uv (uv pip install) для керування залежностями проєкту, оскільки ці команди не оновлюють uv.lock чи pyproject.toml автоматично. Інтерфейс pip може бути корисним для тестування або у не-проєктних середовищах.

Оновлення та видалення залежностей:

Щоб оновити залежність, використовуйте команду uv add з опцією --upgrade:

$ uv add --upgrade <package_name>

Ця команда оновить вказану залежність та оновить її версію у файлі uv.lock.

Щоб видалити залежність, використовуйте команду uv remove:

$ uv remove <package_name>

uv remove також видаляє транзитивні залежності та оновлює pyproject.toml та uv.lock.

Керування залежностями для розробки:

Для залежностей, які потрібні лише для розробки (наприклад, pytest, Ruff), використовуйте uv add з опцією --dev:

$ uv add --dev <package_name>

Ця команда встановить пакунок у віртуальне середовище та додасть його як залежність для розробки до файлів pyproject.toml та uv.lock. У pyproject.toml вони з'являться у секції [dependency-groups.dev].

Блокування та синхронізація середовища

Блокування полягає у фіксації точних залежностей проєкту у файлі uv.lock, забезпечуючи можливість відтворити середовище на будь-якій конфігурації. Синхронізація — це процес встановлення необхідних пакунків із файлу uv.lock у середовище проєкту.

uv автоматично обробляє процеси блокування та синхронізації. Наприклад, при виконанні uv run, проєкт спочатку блокується та синхронізується перед запуском команди, щоб гарантувати актуальність середовища.

Якщо ви відтворюєте середовище з репозиторію, де є код та файли конфігурації uv, але немає віртуального середовища (.venv/), uv автоматично створить його та встановить залежності з uv.lock при першому запуску.

Для перевірки встановлених пакунків та їх версій у віртуальному середовищі проєкту можна використати:

$ uv pip list

Цей список має збігатися з вмістом uv.lock, що підтверджує точне відтворення середовища. Хоча це команда з інтерфейсу uv pip, її використання тут є коректним, оскільки ви отримуєте інформацію, а не змінюєте середовище.

Ви також можете явно заблокувати та синхронізувати ваш проєкт командами:

$ uv lock
$ uv sync

Це може бути корисно для вирішення проблем або щоб переконатись у використанні правильних версій залежностей.

Збірка та публікація пакунків

uv також можна використовувати для збірки та публікації проєктів у репозиторіях, таких як PyPI.

Конфігурація проєкту для збірки:

Щоб підготувати проєкт до збірки, потрібно налаштувати файл pyproject.toml. Для CLI додатків, як-от приклад у джерелі, необхідно вказати точку входу (entry-point script) у секції [project.scripts]:

[project.scripts]
<command_name> = "<module_name>:<function_name>"

Наприклад, rpcats = "main:main" вказує, що команда rpcats запускатиме функцію main() з файлу main.py.

Далі потрібно визначити систему збірки у секції [build-system]. Наприклад, використовуючи Setuptools та Wheel:

[build-system]
requires = [ "setuptools>=<version>", "wheel>=<version>" ]
build-backend = "setuptools.build_meta"

Збірка дистрибутиву:

Використовуйте команду uv build для створення вихідних (sdist) та бінарних (wheel) дистрибутивів вашого проєкту. За замовчуванням вони будуть розміщені у піддиректорії dist/.

$ uv build

Також доступні опції для збірки лише вихідного (uv build --sdist) або лише бінарного (uv build --wheel) дистрибутиву.

Публікація дистрибутиву:

Після збірки пакунок можна опублікувати у репозиторій, наприклад, PyPI. Для тестування рекомендується використовувати TestPyPI. Вам знадобиться обліковий запис та API токен для репозиторію.

Можна налаштувати користувацький індекс для публікації у pyproject.toml під [[tool.uv.index]]:

[[tool.uv.index]]
name = "testpypi"
url = "https://test.pypi.org/simple/"
publish-url = "https://test.pypi.org/legacy/"
explicit = true

Щоб опублікувати пакунок, використовуйте команду uv publish з опцією --index (для користувацького індексу) та --token:

$ uv publish --index <index_name> --token your_token_here

Для публікації у основний індекс PyPI, якщо він не вказаний як користувацький, просто використовуйте:

$ uv publish --token your_token_here

(Примітка: Не публікуйте зразки проєктів на основний PyPI).

Ви можете протестувати встановлення опублікованого пакунку, створивши нове віртуальне середовище за допомогою uv venv у іншій директорії та використовуючи uv pip install з опцією -i для вказівки URL репозиторію.
