Об'єкти, що хешуються

Крім послідовностей в Python є ще дві групи контейнерів — множини та відображення. Але перш ніж детально познайомитись з ними спочатку розглянемо що таке об'єкти, які хешуються.

Серед вбудованих функцій Python є функція hash(), яка повертає хеш для переданого їй об'єкта. Хеш-значенням буде деяке ціле число (int).

Насправді функція hash() викликає магічний метод __hash__() для переданого їй об'єкта. Якщо цей магічний метод об'єктом не реалізовано, то піднімається виняток TypeError.

Об'єкт, що хешується (hashable objects) в Python — такий об'єкт, який має хеш-значення, яке не змінюється протягом життєвого циклу об'єкта (поки його стан не змінюється, якщо це можливо), і обчислюється магічним методом __hash__(), а також цей об'єкт можна порівнювати з іншими об'єктами (реалізує метод __eq__()).

Рівні об'єкти, що хешуються, повинні мати рівні хеш-значення. Якщо два об'єкта, що хешуються, мають рівні хеш-значення, тоді ці об'єкти можливо рівні. Це дозволяє дуже швидко порівнювати між собою складні по структурі об'єкти.

Якщо нам треба перевірити, що два об'єкта не рівні, і якщо ці об'єкти хешуються, то ми можемо зробити це майже миттєво просто порівнявши хеш-значення цих об'єктів. Якщо хеш-значення не рівні, це означає, що об'єкти точно не рівні.

Якщо нам треба перевірити, що два об'єкта рівні між собою, то ми спочатку порівнюємо хеш-значення цих об'єктів, і якщо останні не рівні, то вже можна стверджувати що і самі об'єкти не рівні і далі вже нічого не перевіряти. Це вже є дуже непоганою оптимізацією. Якщо ж хеш-значення рівні, то далі ми вже порівнюємо значення самих об'єктів.

Все це дозволяє шукати об'єкти, що хешуються, серед інших об'єктів дуже швидко.

Ця можливість в першу чергу використовується в таких структурах даних, як хеш-таблиці, які лежать в основі реалізації відображень (наприклад dict) та множин (set) в Python.

Коли потрібно зберегти або знайти елемент у словнику чи множині (які використовують хеш-таблиці):

  1. Python обчислює хеш-значення елемента.
  2. За цим хеш-значенням швидко визначається конкретне місце в пам'яті, де елемент має зберігатися або де його шукати.
  3. Елемент або додається у це визначене місце, або шукається лише серед небагатьох елементів, що можуть там знаходитися.

Це працює "дуже швидко", бо замість перебору всіх елементів у великій колекції, Python одразу переходить до потрібного місця в пам'яті. В ідеалі, кожне таке місце містить дуже мало елементів, тому пошук, додавання чи видалення відбуваються майже миттєво.

Іноді різні елементи можуть отримати однакове хеш-значення (колізія). Python має способи вирішення таких ситуацій, щоб все одно працювати ефективно.

Таким чином, використання хеш-значень у поєднанні з хеш-таблицями є фундаментальною причиною такої високої ефективності операцій зі словниками та множинами в Python.

Усі стандартні мутабельні об'єкти Python не є такими, що хешуються.

Усі стандартні немутабельні об'єкти є такими, що хешуються, якщо вони не містять у собі мутабельних об'єктів.

>>> hash('hello')
1001890812597159072
>>> hash(None)
84759117
>>>

Хеш від цілого числа в CPython — зазвичай саме число (крім дуже великих), але це не гарантується специфікацією Python для всіх реалізацій:

>>> hash(42)
42
>>>

Від мутабельних об'єктів:

Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: unhashable type: 'list'
>>>

Також у контейнерах не має бути мутабельних об'єктів:

>>> hash((1,2,3))
2528502973977326415
>>> hash((1,[2],3))
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: unhashable type: 'list'
>>>

Функція hash() містить дві "пасхалки" (специфічно для CPython, може змінюватися): 

>>> hash(float('inf')) # перші цифри числа Пі
314159
>>> hash(float('NaN'))
0
>>>

Трапляються і колізії: 

>>> hash(-1), hash(-2)
(-2, -2)
>>>

Метод __hash__

Метод __hash__(self) повинен повертати ціле число. Це число використовується для визначення позиції об'єкта в хеш-таблиці.

Основні властивості __hash__:

  1. Якщо два об'єкти рівні (тобто a == b повертає True), то їхні хеш-коди також повинні бути рівними (hash(a) == hash(b)).
  2. Зворотне не обов'язково вірне: якщо hash(a) == hash(b), це не означає, що a == b. Така ситуація називається колізією хешів. Хеш-таблиці розроблені так, щоб обробляти колізії.
  3. Об'єкт, який використовується як ключ словника або елемент множини, повинен мати незмінний хеш-код протягом усього свого життя, поки він знаходиться в цій колекції. Якщо хеш-код об'єкта змінюється, його неможливо буде знайти в колекції.

Для вбудованих незмінних типів ( int, str, tuple, frozenset) __hash__ вже реалізований.

Якщо ваш клас не перевизначає метод __eq__, то за замовчуванням він успадковує __hash__ від object. Цей __hash__ базується на ідентифікаторі об'єкта (id(self)), тому кожен екземпляр матиме унікальний хеш. Відповідно об'єкти будуть рівні лише самі собі:

>>> class MyClass:
...     pass
...
>>> obj1 = MyClass()
>>> obj2 = MyClass()
>>> hash(obj1)  # Унікальний хеш для obj1
123456789
>>> hash(obj2)  # Унікальний хеш для obj2
987654321
>>> obj1 == obj2
False
>>> hash(obj1) == hash(obj2)  # Хеші не рівні
False
>>> obj1 is obj2  # Об'єкти різні
False
>>> obj1 == obj1  # Об'єкт рівний сам собі
True

Важливе правило: якщо a == b істинно, то hash(a) == hash(b) також має бути істинним.

Якщо ви перевизначаєте __eq__ для свого класу, ви також повинні перевизначити __hash__, або явно встановити __hash__ = None, якщо об'єкти не повинні бути хешованими.

Якщо клас перевизначає __eq__, але не перевизначає __hash__, то Python автоматично встановлює __hash__ = None. Це робить екземпляри класу нехешованими, і їх не можна буде використовувати як ключі словників або елементи множин. Це зроблено для того, щоб уникнути порушення правила "рівні об'єкти повинні мати рівні хеші", якщо розробник забуде реалізувати __hash__ відповідно до __eq__.

class Person:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age

    def __eq__(self, other):
        if not isinstance(other, Person):
            return NotImplemented # Важливо для коректної роботи з іншими типами
        return self.name == other.name and self.age == other.age

    def __hash__(self):
        # Хешуємо на основі атрибутів, які використовуються в __eq__
        # Використання кортежу є хорошою практикою, оскільки кортежі незмінні
        # і мають власний коректний __hash__.
        return hash((self.name, self.age))

    def __repr__(self):
        return f"Person('{self.name}', {self.age})"

a = Person("Alice", 30)
a2 = Person("Alice", 30) # Такий самий, як a
b = Person("Bob", 25)

У цьому прикладі __hash__ обчислюється на основі кортежу (self.name, self.age). Оскільки self.name та self.age використовуються для перевірки рівності в __eq__, це забезпечує виконання вищезазначеного правила.

>>> a == b
False
>>> hash(a) == hash(b)
False
>>> a == a2
True
>>> hash(a) == hash(a2)
True
>>>

Якщо значення атрибутів, що використовуються для обчислення хешу, змінюються після того, як об'єкт був доданий до словника чи множини, його хеш також зміниться. Це призведе до того, що об'єкт "загубиться" в колекції, оскільки Python шукатиме його в іншій "комірці" хеш-таблиці.

Саме тому вбудовані мутабельні типи, такі як списки або словники, не можуть бути ключами словників або елементами множин. Вони не мають реалізації __hash__, точніше, їх __hash__ встановлено в None.

>>> {[1]: "oops"}
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: unhashable type: 'list'
>>>

Тобто тип даних list не є хешованим.

Якщо ваш клас містить змінні атрибути, але ви все одно хочете зробити його хешованим, ви повинні гарантувати, що атрибути, які використовуються в __hash__ та __eq__, не будуть змінюватися. Або, якщо вони можуть змінюватися, екземпляри такого класу не повинні використовуватися в хеш-колекціях після зміни.

Метод __hash__ завжди повинен повертати ціле число (int).

Успадкування та __hash__

  • Якщо батьківський клас реалізує __eq__ та __hash__, а дочірній клас перевизначає __eq__, то дочірній клас також повинен перевизначити __hash__. Якщо цього не зробити, успадкований __hash__ може не відповідати новому __eq__.
  • Якщо дочірній клас не перевизначає __eq__, він успадкує __eq__ та __hash__ від батька.
  • Якщо дочірній клас перевизначає __eq__, але не __hash__, то __hash__ дочірнього класу автоматично стане None.

Найкращі практики для __hash__

__hash__ потрібен, якщо:

  • Ви хочете, щоб екземпляри вашого класу можна було використовувати як ключі у відображеннях (наприклад dict).
  • Ви хочете, щоб екземпляри вашого класу можна було додавати до множин (set або frozenset).
  • Ви реалізуєте власний __eq__ і хочете, щоб об'єкти були хешованими.

__hash__ не потрібен (або має бути None), якщо:

  • Екземпляри вашого класу є мутабельними таким чином, що їхня рівність або хеш-значення можуть змінитися після створення.
  • Логіка рівності (__eq__) занадто складна, і забезпечити узгодженість з __hash__ важко або недоцільно.
  • Ви просто не плануєте використовувати екземпляри класу в хеш-колекціях.

Метод __hash__ повинен бути відносно швидким, оскільки він викликається кожного разу, коли об'єкт додається до хеш-колекції або шукається в ній. Уникайте складних обчислень у __hash__.
